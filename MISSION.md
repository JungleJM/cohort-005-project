# Mission: How refunds work in Cadence

## Why
Have an accurate mental model of the refund flow in this codebase, so conversations and decisions about it rest on what the system really does.

## Success looks like
- Walk through a refund from the learner's click to where the flow stops, from memory
- Say what the learner and staff each see at every stage
- Tell which parts are built and which are only implied by the schema or the copy

## Constraints
- Goal is understanding, not delivery. Lessons stay short and explain behaviour before code.

## Out of scope
- Building the approval flow (the learner chose understanding over implementation on 2026-11-09)
- Payment provider integration details
